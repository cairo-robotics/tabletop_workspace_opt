# Arrival-Based Termination: Full Rerun Plan (2026-04-15)

## Context
We added arrival-based termination to the SE(3) SA control loop
(`run_headless_sa_se3` in `scripts/run_sa_headless.py`). When the EE
reaches within `arrival_dist` of the true target, the loop commits on
the current argmax rather than loitering until stall. This matches the
behavior of a deployed system where the user physically arrives at the
goal. The change was driven by the Hard-B DE failure analysis, which
showed 83/240 argmax-wrong picks, all of which confused with
`green_cylinder` due to path-length inflation during loiter.

All tiers/conditions are being rerun so the main results table and
figures reflect the new termination rule consistently.

### Notable changes vs. stall-terminated results

- **DE Hard-A: 99% → 100%.** Arrival termination eliminates the 1%
  stall-tail drift that had been flipping argmax near end of loiter.
- **ME Hard-A: 100% → 100%** (unchanged, seed-45 layout).
- **ME Hard-B: 97% → 100%.** Arrival eliminates the 3% residual.
- **DE Hard-B: 67% → 28%.** Arrival termination makes the Hard-B DE
  failure more deterministic rather than stochastic. Under stall
  termination, the very long tail averaged over many noise-induced
  argmax flips, partially masking the underlying geometric bias.
  Under arrival, the loop exits at a fixed geometric point (EE at
  $2$\,cm) where the cost ratio deterministically favors
  \texttt{green\_cylinder}. The true argmax accuracy of DE's Hard-B
  layout under the deployed-system semantics is ${\approx}28\%$.
  The 100% vs 28% ME/DE gap is now the headline result.
- **DE Hard-A pick time: 10.9 s → 10.2 s.** Modest speedup from
  earlier exit.
- **Random baselines** are now evaluated under identical termination
  rule as DE/ME (arrival-based), so all three conditions are
  apples-to-apples.
